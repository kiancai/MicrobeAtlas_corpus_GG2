# 2026-06-05 Qiita 数据评估与落地准备

## 触发
扩样本行第二主力 = Qiita。评估它的规模/净新增/接入方式，并准备并入语料。过程中用户两处关键修正：
1. **不限人体**：之前扩增计划写"下游只用于人体"是错的——现有语料 MCFCorpus 本就是全环境，预训练大模型要全样本。Qiita **取全部样本，不按 host 筛**。
2. **注释全注释、不管重复**：能注释的 16S 全注释；去重是下游(Layer2)筛选的事，不作注释门槛。与 merge-then-filter 架构一致。

## 简介
用户从 Qiita 官网下了整包「public BIOM + metadata」(99G)放到 `rawdata/Qiita/`。我在不整包解压(先只抽 templates 小文件、再在腾出空间后解 BIOM)的前提下，盘点了数据全貌、建了 ENA 去重桥、算了净新增。**结论：Qiita 是目前最大单一净新增源，且数据干净(给精确 ASV 序列)。**

## 核心结论

### 1. 数据全貌（实测，详见 `data/qiita.md`）
- 873 study，**784 含 16S 且基本纯 16S**（仅 42 个混 ITS/18S）→ 按**样本/prep 粒度**筛 16S，不能整 study 拿。
- **16S 样本 362,011；有 ASV 序列、能注释 = 324,220**（其余 3.8 万只有闭合参考 OTU，无序列）。
- 环境 ~72% host-associated（人+动物，以肠道为主）/ ~14% 环境 / ~5% 控制。
- metadata 丰富：host_subject_id 97.5% + collection_timestamp 89%（同人/时序金矿）、empo/geo/部位较全，年龄性别偏稀。

### 2. 接入方式
- 模板 `run_prefix` 不是 accession → 包内无 SRA 号。去重靠 **ENA UCSDMI 桥**（`sample_alias=qiita_sid_<study>:<样本名>` → run + first_public + BioSample），已拉全表 `qiita_ena_bridge.tsv`(372,512 run)。
- redbiom 要直连 `qiita.ucsd.edu:7329`（项目代理弄坏 keepalive），且批量 metadata 大批会被拒 → 改用整包 templates 拿全 metadata。
- 注释路径 NB(本地现成/一致) vs exact-match(需下 .asv 表/更省)，**待 pilot 定**。

### 3. 净新增（Layer2 参考，非注释门槛）
- net-new(不在 corpus∪MBM) = 223,011；有 ASV 表 185,642。
- 分档：🟢铁(MA 2.69M 也没见过, ~全 post-2021)=81,304 / 🟡 MA见过被QC剔=39,372 / ⚪无桥未验证=102,335。
- **比 MicroBioMap 净新增(6.2万)大；专补 MA 2021-01 快照之后的时间盲区。**

### 4. Layer1 ✅ 完成（2026-06-05，按 `merge_architecture.md` 契约）
**产物 `qiita.gg2.genus.h5ad` = 321,502 样本 × 6,954 genus** counts（134 亿 reads / 真 genus 5,745 / 零行 13 / 全样本不筛不去重）。
- 方法 **B（全局去重，复用 RM/MBM）**：选表(每样本1张90nt 16S，混合study prep-Jaccard锁16S)→ 全局去重 1670万 ASV → 67 片 GG2 full-length NB(both) → per-study collapse(RM03/MBM05逐字) → 拼表。流水线/坑详 `data/qiita.md` §4。
- 选 B 不选 per-study A：A 累计 2567 万 ASV + 233 万怪兽单作业；B 1670 万、均匀切片、无怪兽、结果等价（NB 逐序列确定性）。
- ⚠ 坑：含长 ASV(150/250nt) 的分片 128G OOM（5/67 片）→ 400G 救回。
- ⚠ obs 主键 `study.sample` 非 run；Run 经 ENA 桥映射(~30.9 万有)，其余 Layer2 标 `dedup_uncertain`。
